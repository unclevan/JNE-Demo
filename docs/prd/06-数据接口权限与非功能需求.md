# 数据、接口、权限与非功能需求

## 1. 文档目的

本文件定义产品研发必须共同遵守的系统边界和质量要求。具体数据库、消息中间件、模型和部署技术由技术方案确定，但不得削弱本文要求的可追溯、权限、安全和验收能力。

## 2. 建议逻辑架构

```text
原江南 e 前端 / AI 管理后台 / 数据驾驶舱
                    │
               统一 API 网关
                    │
├─ 用户与权限服务
├─ AI 会话编排服务
├─ 标的检索与推荐服务
├─ 资产解析任务服务
├─ 知识检索与规则服务
├─ 智能撮合与触达服务
├─ 风险线索与处置服务
├─ 指标查询与报告服务
└─ 审计与通知服务
                    │
├─ 原业务系统接口/事件
├─ 数据仓库与指标层
├─ 文档/对象存储
├─ 向量检索与全文检索
├─ 大模型统一网关
└─ 经授权的地图/公共数据
```

## 3. 核心数据对象

### 3.1 业务映射对象

| 对象 | 关键标识 | 关键字段 | 说明 |
|---|---|---|---|
| 项目 | project_id | 编号、名称、机构、产权人、状态 | 使用原系统主键 |
| 标的 | asset_item_id | 名称、类型、区域、面积、价格、期限 | 一个项目可含多个标的 |
| 资产实体 | asset_id | 位置、权属、历史项目关联 | 支持再次挂牌和长期运营 |
| 公告 | notice_id/version | 类型、正文、发布和有效时间 | 版本不可覆盖 |
| 附件 | file_id/hash | 名称、类型、大小、权限、病毒扫描结果 | 内容变更产生新 hash |
| 主体 | subject_id | 类型、区域、行业、认证状态 | 敏感信息单独保护 |
| 报名 | application_id | 主体、标的、状态、时间 | 原系统权威数据 |
| 竞价行为 | bid_id | 主体、标的、报价、时间 | 严格权限和审计 |
| 成交 | transaction_id | 标的、成交价、时间、状态 | 正式效能指标来源 |

### 3.2 AI 与运营对象

| 对象 | 关键标识 | 关键字段 |
|---|---|---|
| AI 会话 | conversation_id | 用户、入口、上下文、开始/结束、状态 |
| AI 消息 | message_id | 角色、内容、引用、模型版本、耗时、安全结果 |
| 解析任务 | parse_job_id | 对象、输入版本、阶段、状态、错误、耗时 |
| 解析字段 | parsed_field_id | 字段、提取值、来源、置信度、确认值、状态 |
| 分析版本 | analysis_version_id | 输入/模型/规则/知识版本、输出、发布状态 |
| 匹配关系 | match_id | 标的、主体、总分、分项、理由、版本 |
| 撮合任务 | match_task_id | 资产、候选范围、目标、负责人、状态 |
| 触达批次 | campaign_id | 渠道、模板、对象、审核、发送、结果 |
| 知识文档/条目 | doc_id/chunk_id | 来源、内容、适用范围、版本、权限、有效期 |
| 业务规则 | rule_id/version | 条件、等级、提示、适用范围、状态 |
| 风险线索 | risk_clue_id | 来源、对象、依据、概率、影响、状态 |
| 风险事件 | risk_event_id | 聚合线索、等级、负责人、处置和结论 |
| 指标定义 | metric_id/version | 名称、维度、公式、单位、刷新和责任人 |
| 报告任务 | report_job_id | 模板、范围、版本、状态、文件和过期时间 |

## 4. 数据同步

### 4.1 同步方式

优先采用业务事件或增量接口：

- 项目创建/变更/撤牌；
- 标的创建/变更；
- 公告发布/变更/失效；
- 报名状态变更；
- 资格审查结果；
- 竞价开始/结束；
- 成交确认/变更；
- 主体认证状态变更。

无法提供事件时，使用按更新时间增量拉取，并每日进行全量对账。

### 4.2 同步要求

- 幂等：同一事件重复消费不产生重复业务对象；
- 顺序：同一项目的状态事件按版本或时间有序处理；
- 补偿：失败进入重试队列，超过阈值转人工；
- 对账：记录源数量、目标数量、差异和修复结果；
- 删除：源系统删除或撤回时按业务语义停用，不直接物理删除审计数据；
- 延迟：关键交易状态目标 5 分钟内，具体以技术调研为准。

## 5. 接口域与功能边界

以下为逻辑接口，不限定最终 URL。

### 5.1 上下文与搜索

- 获取页面/用户上下文；
- 自然语言条件解析；
- 标的结构化搜索；
- 获取推荐结果和匹配理由；
- 获取项目/标的公开详情；
- 获取本人业务状态（需登录和鉴权）。

### 5.2 AI 会话

- 创建、继续、结束和删除会话；
- 流式返回回答；
- 返回引用、建议问题和操作卡片；
- 提交评价、转人工和问题反馈；
- 查询本人历史会话。

### 5.3 资产解析

- 创建/重跑/终止解析任务；
- 查询任务状态和阶段；
- 获取字段、来源和冲突；
- 确认/修改字段；
- 提交复核/审批/发布；
- 获取公开分析版本；
- 创建和下载报告。

### 5.4 撮合与触达

- 查询撮合机会和候选主体；
- 获取匹配分项和理由；
- 创建/审核/执行撮合任务；
- 创建/审核/发送触达批次；
- 回传送达、查看、咨询和转化事件。

### 5.5 知识与规则

- 上传/解析文档；
- 编辑条目和 FAQ；
- 创建/测试/发布规则；
- 版本发布、回滚和下线；
- 按权限和有效期检索知识。

### 5.6 风险

- 创建/聚合风险线索；
- 分派、领取、核验和转办；
- 提交处置、复核和关闭；
- 查询风险矩阵和规则效果。

### 5.7 驾驶舱与报告

- 获取全局筛选字典；
- 查询指标卡、趋势、结构、漏斗、地图和排行；
- 查询钻取明细；
- 创建 Excel/PDF 导出任务；
- 查询导出状态和下载。

## 6. 接口通用规范

- 统一认证和授权；
- 请求携带 trace_id，响应返回 request_id；
- 写接口支持幂等键；
- 时间统一使用带时区的 ISO 8601，前端按 Asia/Shanghai 展示；
- 金额使用最小货币单位或高精度 decimal，禁止浮点误差；
- 面积、期限、价格均返回数值和单位；
- 列表统一分页、排序和筛选协议；
- 错误响应包含稳定错误码、用户可读提示和可选的排障信息；
- 批量任务使用异步任务 ID，不保持长连接等待；
- 关键接口记录调用方、数据范围、输入摘要、结果和耗时。

## 7. 指标与数据治理

### 7.1 指标字典

每个指标至少包含：编码、名称、业务定义、计算公式、分子分母、单位、维度、过滤条件、去重主键、时间口径、刷新频率、数据来源、负责人、版本和生效时间。

### 7.2 一致性

- 卡片、图表、明细和导出必须调用同一指标版本；
- 同一名称不得存在多个未说明的计算口径；
- 指标变更需影响分析和版本发布；
- 历史指标原则上按当时版本保留，重算时标明重算版本；
- 缺失值、0 和不适用必须区分。

### 7.3 数据质量

至少监控：完整性、唯一性、一致性、及时性、有效性和对账差异。异常生成数据质量事件，并可影响驾驶舱的“数据可信状态”。

## 8. 权限模型

### 8.1 权限维度

- 功能权限：菜单、页面、按钮和接口；
- 数据权限：机构、区域、业务板块、项目、主体；
- 字段权限：个人敏感信息、报价明细、内部备注、模型配置；
- 操作权限：查看、导出、复核、审批、发布、触达、关闭风险；
- 环境权限：开发、测试、生产隔离。

### 8.2 权限原则

1. 默认拒绝，按最小权限授权；
2. 前端隐藏不等于权限控制，后端必须校验；
3. 系统管理员不默认拥有业务敏感明文权限；
4. 导出权限独立于查看权限；
5. 批量触达、知识发布、风险关闭、模型配置建议采用审批或双人控制；
6. 临时授权需设到期时间并记录审批依据。

## 9. 敏感数据与隐私

### 9.1 敏感数据示例

- 姓名、手机号、身份证号；
- 统一社会信用代码在非必要场景下的完整值；
- 银行账号和保证金支付信息；
- 报价明细、设备/IP、账号关联；
- 未公开项目、内部审核意见和风险处置材料；
- 模型密钥、接口凭据和安全策略。

### 9.2 控制要求

- 传输全程加密，敏感字段存储加密或令牌化；
- 页面默认脱敏，查看明文需单独权限并记录日志；
- 发往模型前执行字段级过滤和脱敏；
- 非必要不得将个人身份信息写入提示词、向量库和普通应用日志；
- 测试环境使用脱敏或合成数据；
- 导出文件带水印、有效期和访问控制；
- 数据保留和删除期限由业主制度及法律要求确认。

## 10. AI 治理

### 10.1 模型网关

统一管理模型路由、认证、超时、重试、限流、成本、内容安全和日志。禁止业务应用直接调用外部模型。

### 10.2 可追溯信息

每次 AI 输出保留：场景、用户/系统身份、业务上下文版本、模型、参数、提示词版本、检索文档和片段、规则结果、输出、安全处理、耗时和反馈。

### 10.3 评测

建立固定评测集，覆盖：找标的、时间、保证金、资格、成本、政策、资产解析、冲突字段、拒答和敏感信息。模型、提示词或知识版本发布前必须回归。

### 10.4 人工控制

- 公开资产分析需经过规定的人工复核；
- 风险线索不得由 AI 自动作最终认定；
- 批量触达需人工审核；
- 高风险回答场景使用结构化数据和规则优先，模型只负责组织表达；
- 支持紧急关闭某模型、某场景或全部生成式能力，降级至检索/FAQ。

## 11. 安全要求

- 对接统一身份认证，建议支持单点登录和多因素认证（管理端）；
- 防止越权访问、注入、跨站脚本、请求伪造和文件上传风险；
- 文档上传执行类型校验、病毒扫描、大小限制和隔离处理；
- 防范提示词注入：知识文档内容视为数据，不作为系统指令执行；
- 检索结果按用户权限过滤后再送入模型；
- API 限流、防刷和异常访问告警；
- 安全漏洞和依赖升级按业主制度处理；
- 满足适用的等保、日志审计和数据出境要求，具体等级待确认。

## 12. 性能要求

以下为首期建议目标，需技术评审确认：

| 场景 | 指标 |
|---|---|
| 门户助手打开 | P95 ≤ 1 秒（不含首次静态资源） |
| 普通业务查询 | P95 ≤ 2 秒 |
| AI 首字响应 | P95 ≤ 3 秒；完整回答 P95 ≤ 12 秒 |
| 标的搜索 | P95 ≤ 2 秒 |
| 驾驶舱首屏 | P95 ≤ 5 秒，核心卡片优先返回 |
| 驾驶舱筛选 | P95 ≤ 3 秒；复杂钻取 ≤ 5 秒 |
| 单项目资产解析 | 90% ≤ 2 分钟；大文件异步处理 |
| 列表导出 | 10 万行以内异步 5 分钟完成 |
| 并发 | 根据实际访问量压测，首期容量需保留 2 倍峰值余量 |

## 13. 可用性与容灾

- 核心查询与管理服务月可用性目标建议 ≥ 99.9%；
- 模型不可用不影响原交易业务；
- AI 服务支持模型切换和检索/FAQ 降级；
- 驾驶舱单模块失败不影响全页；
- 任务队列支持重试、死信和人工恢复；
- 数据库、对象存储和配置按运维要求备份；
- 明确 RPO/RTO，建议首期 RPO ≤ 15 分钟、RTO ≤ 2 小时，最终由业主确认。

## 14. 可观测性

监控：接口成功率和耗时、模型调用、Token/成本、任务队列、数据同步延迟、解析失败、知识检索空结果、回答安全拦截、驾驶舱数据延迟、导出失败和风险待办积压。

日志需分为应用日志、业务审计日志、AI 调用日志和安全日志；不同日志采用不同权限和保留期。

## 15. 兼容性与可访问性

- 重点支持业主办公环境中的 Chrome/Edge 当前及前两个主要版本；
- 适配 1366×768、1920×1080 和常见 2K 屏；
- 门户助手支持移动端；驾驶舱首期以桌面端为主；
- 键盘可操作、焦点可见、图表提供文本替代、颜色不作为唯一信息载体；
- 中文字体缺失时使用安全回退字体。

## 16. 测试要求

### 16.1 测试类型

- 单元、接口、集成、端到端；
- 权限和越权；
- 数据对账和指标回归；
- AI 固定评测集回归；
- 文件解析兼容性；
- 性能、稳定性和故障降级；
- 安全扫描和渗透测试；
- 用户验收测试。

### 16.2 上线门槛

- P0 功能验收通过；
- 高危安全问题为 0；
- 核心指标对账通过；
- 高风险问答评测错误为 0；
- 降级和回滚演练通过；
- 权限矩阵和审计日志经业主确认；
- 上线、回滚、数据补偿和应急联系人文档齐备。
