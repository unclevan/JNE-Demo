# 研发分期与验收清单

## 1. 分期原则

1. 先打通原平台数据和权限，再上线生成式能力；
2. 先保证回答有依据、结果可复核，再扩展个性化和自动化；
3. 先建立触达与交易行为的可追踪链路，再评价 AI 对竞买人数和溢价率的贡献；
4. 驾驶舱指标随数据接入逐步替换模拟数据，禁止以模拟数据进入生产；
5. 批量触达、风险判断和公开分析保留人工控制。

## 2. 建议版本范围

### 2.1 V1.0：可用闭环（MVP）

目标：形成“可问、可解析、可复核、可观察”的最小生产闭环。

#### 原平台嵌入

- 首页/公共页面 AI 助手；
- 标的详情页情境化助手；
- 找标的、项目基础信息、报名/竞价/保证金/资格/时间/政策问答；
- 推荐卡片和详情跳转；
- 回答引用、评价、转人工和降级。

#### AI 资产解析

- 项目、标的、公告和常见 PDF/Word 附件解析；
- 资产画像、基础成本测算、风险与材料提示；
- 投资价值和周边资源可在数据授权后按简版上线；
- 人工字段复核、版本发布和报告导出。

#### 管理后台

- 工作台；
- 解析任务和字段复核；
- 会话查询、未解决问题和反馈；
- 知识文档、FAQ、基础规则和发布；
- 风险线索基础处置；
- 用户、角色、字典、AI 配置和审计。

#### 驾驶舱

- 六个分页的核心卡片和主要图表；
- 时间、区域、板块和类型筛选；
- 指标说明、明细钻取和基础导出；
- 交易效能页重点上线触达、竞买人数和溢价率分析；
- AI 洞察页上线解析、会话和质量指标。

### 2.2 V1.5：运营增效

- 主体画像与智能撮合候选；
- 撮合任务、站内触达和转化跟踪；
- 资产类型差异化评分模型；
- 历史成交参考和周边资源正式数据；
- 风险事件聚合和完整闭环；
- 自动经营摘要和异步管理报告；
- AI 效果按类型、区域和时间精细分析。

### 2.3 V2.0：规模化与优化

- 经授权的多渠道触达；
- 个性化推荐和召回；
- 更完整的异常竞价辅助模型；
- 统计归因、对照组或准实验分析；
- 模型评测平台、灰度发布和自动回归；
- 跨区域、跨机构多租户能力；
- 移动管理端和更多经营场景。

## 4. 里程碑建议

具体工期需在接口调研、UI 定稿和团队配置后估算。建议里程碑顺序：

1. **M0 需求基线**：PRD、流程、权限矩阵、指标字典和数据清单评审通过；
2. **M1 技术底座**：环境、认证、网关、数据同步、模型网关和知识库可用；
3. **M2 内部 Alpha**：后台、基础问答、基础解析和核心指标可联调；
4. **M3 业务 Beta**：嵌入原平台，业务人员完成复核和 UAT；
5. **M4 试运行**：小范围用户、真实数据、监控和人工兜底；
6. **M5 正式上线**：问题收敛、应急演练、资料交付和上线验收；
7. **M6 效果复盘**：累计足够周期后评估触达、竞买人数和溢价变化。

## 5. 跨团队前置清单

### 5.1 业主/业务

- 确认资产、项目、标的及各交易状态定义；
- 确认报名、竞价、保证金、资格和优先权规则；
- 提供政策、公告模板、FAQ 和人工服务流程；
- 确认 AI 公开展示边界、风险用语和免责声明；
- 确认指标口径、基准期及“AI 辅助项目”定义；
- 确认角色、组织和数据权限。

### 5.2 原平台厂商

- 提供前端嵌入、登录态和页面上下文方案；
- 提供项目、标的、公告、附件和交易流程接口；
- 提供用户行为埋点或跳转回传能力；
- 提供测试环境、接口文档和错误码；
- 确认生产发布和回滚协作方式。

### 5.3 数据/技术

- 确认数据仓库、指标服务和报表现状；
- 确认主体数据、历史成交和地图/公共数据授权；
- 确认大模型部署和数据出境限制；
- 确认等保、密码、日志、备份和容灾要求；
- 建立脱敏测试数据和固定 AI 评测集。

### 5.4 UI

- 输出驾驶舱六页、后台组件和前台 AI 组件设计；
- 提供桌面端、移动端和异常/空状态；
- 定义图表颜色、单位、tooltip、钻取和加载状态；
- 明确与原平台视觉系统的共用组件和差异。

## 6. 全产品验收清单

### 6.1 原平台嵌入

- [ ] 助手入口不影响原页面主要功能和性能；
- [ ] 登录态、用户权限和页面上下文传递正确；
- [ ] 首页和详情页使用正确的欢迎语与快捷问题；
- [ ] 推荐卡片能跳转正确标的；
- [ ] 页面切换、返回和浏览器前进后退无异常；
- [ ] 模型故障不影响原报名和竞价流程。

### 6.2 AI 智能咨询

- [ ] P0 意图均通过测试样本；
- [ ] 实时关键字段来自业务接口；
- [ ] 回答显示引用和更新时间；
- [ ] 缺失、冲突、超时和越权时正确降级；
- [ ] 评价、转人工和后续转化可追踪；
- [ ] 敏感输入和日志完成脱敏；
- [ ] 模型/知识/提示词版本可追溯。

### 6.3 AI 资产解析

- [ ] 自动触发、重跑、失败重试和幂等有效；
- [ ] 核心字段可定位到原文；
- [ ] 人工复核、审批、发布和版本有效；
- [ ] 五个模块按数据可用性展示；
- [ ] 成本公式、评分和风险规则经业务确认；
- [ ] 报告可生成、下载、过期和审计；
- [ ] 未发布和内部字段不对外泄露。

### 6.4 管理后台

- [ ] 菜单、按钮、数据和字段权限正确；
- [ ] 工作台待办与实际任务一致；
- [ ] 会话、知识、解析、撮合和风险状态机可闭环；
- [ ] 批量操作、发布和触达均有确认与审计；
- [ ] 任务失败、超时和同步异常可处理；
- [ ] 列表、详情、筛选、导出和操作记录完整。

### 6.5 数据驾驶舱

- [ ] 六页 UI 和交互符合定稿；
- [ ] 全局筛选和权限生效；
- [ ] 指标、图表、明细和导出可勾稽；
- [ ] 每项指标可查看公式、来源和更新时间；
- [ ] 交易效能按时间、类型和区域展示触达、竞买人数及溢价；
- [ ] 风险和 AI 洞察可跳转后台处理；
- [ ] 空数据、延迟、接口失败和地图失败均可降级。

### 6.6 安全和非功能

- [ ] 性能压测达到确认目标；
- [ ] 越权、注入、文件上传和提示词注入测试通过；
- [ ] 生产无前端密钥和明文敏感配置；
- [ ] 日志、监控和告警可用；
- [ ] 备份、恢复、降级和回滚演练通过；
- [ ] 数据保留、删除和导出符合制度；
- [ ] 上线文档、运维手册和应急联系人齐备。

## 7. 待业主确认事项

以下问题会影响技术方案或开发范围，应在需求基线前确认：

1. 首期正式用户范围：仅内部试用，还是同时面向公众开放？
2. 原平台技术栈、登录方式以及允许的嵌入方式是什么？
3. 原平台能否提供实时项目、公告、报名、竞价和成交接口或事件？
4. 是否允许 AI 查询登录用户本人的报名、保证金和资格状态？
5. 资产解析结果是否需要业务人员审批后对外展示？是否双人复核？
6. 历史成交、人口、企业、地图和产业数据是否已有授权数据源？
7. 是否启用短信、邮件、企业微信等主动触达？用户同意如何取得？
8. 主体画像和信用/履约信息允许使用到什么粒度？
9. AI 模型采用本地私有化、政务云服务还是经批准的外部服务？
10. 数据是否允许出域，日志和会话需要保留多久？
11. 等保等级、密码应用、审计和容灾指标是什么？
12. 驾驶舱“AI 辅助前后”的基准期和 AI 辅助项目定义是什么？
13. 溢价率采用总额加权、项目平均还是两种同时展示？
14. 风险线索的正式处理部门、SLA 和关闭权限如何划分？
15. 首期是否需要移动端、国产浏览器或信创环境适配？

## 8. 建议下一步

1. 组织一次产品范围评审，确认 V1.0/P1/P2；
2. 组织原平台技术和数据接口调研；
3. 输出角色权限矩阵、业务状态机和指标字典确认版；
4. UI 基于本 PRD 补齐后台页面、异常状态和交互稿；
5. 技术团队输出架构方案、接口清单、数据模型和工期评估；
6. 选取 20—50 个脱敏真实项目建立解析和问答评测集；
7. 在真实数据接入前保留 Demo 作为视觉原型，不直接演进为生产代码。
